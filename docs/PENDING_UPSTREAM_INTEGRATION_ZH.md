## 2. 当前已确认的问题

### 2.1 异常与未闭环覆盖不完整

VPS 实际保存了 17 条已恢复异常，当前活动异常为 0。用户看到“运行时遥测有报错、异常页没有记录”的主要原因是：

1. 页面默认只展示“当前异常”，恢复后的记录进入“已恢复历史”。
2. Trader 旧失败之后只要出现新成功周期，部分旧任务失败不再作为当前异常展示。
3. 异常检测器主要覆盖 Trader、执行台账、持仓、保护单、心跳和安全门；Backend、Scheduler、自进化、台账同步等任务的错误仍可能只出现在运行时遥测或日志中。
4. 当前模型偏向保存异常的最终状态，而不是把每次异常发生作为不可变事件长期展示。

风险：短暂但重要的异常恢复后不易发现，用户无法从异常页完整追溯系统运行质量。

### 2.2 自进化未读取 Gate 平仓样本

当前台账已有 6 笔完整平仓，但自进化报告显示 0 笔，根因已经定位：

- Gate 台账使用 `BTC_USDT`、`ETH_USDT` 等合约名。
- 自进化标的池使用 `BTC`、`ETH` 等基础币名称。
- `load_closed_trades()` 使用未经归一化的精确匹配，导致所有 Gate 平仓被过滤。
- 当前自进化标的池仍包含 `LINK`，而实际交易池已经使用 `XRP`，存在配置漂移。

因此 02:00 复盘得到 `NO_CHANGE`，08:00 和 14:00 又判断“没有新的平仓证据”。这不是策略基于 6 笔样本决定不改变，而是复盘器根本没有读到这些样本。

### 2.3 首页“成交笔数”与台账口径不同

首页今日统计使用 Gate Futures `account_book`：

- 净盈亏 = `pnl + fee + fund`。
- 当前“成交笔数” = 正负 `pnl` 账本事件数量。

Gate 对一笔仓位平仓可能产生多条分批成交 PnL 事件。例如 XRP 一次仓位退出产生了 6 条 PnL 结算，因此首页显示 9，而台账按完整 `position_close` 聚合后的平仓仓位数更少。

这不是虚构交易，但“成交笔数”的名称和用户理解不一致。

### 2.4 当前提示词存在双套风控数值

旧基础提示词仍包含固定建议，例如：

- 保证金 `100~200U`。
- 杠杆 `2x~5x`。
- 执行置信度门槛 `75%`。
- 单标的累计保证金 `600U`。
- 固定的加仓与锁盈阈值。

Gate 适配器随后又追加当前风险档位、实际杠杆和资金上限，并声明动态值覆盖旧值。虽然执行层仍以 Gate 配置为准，但模型同时看到两套数值，存在理解冲突和输出漂移风险。

### 2.5 System 提示词布局可能未完整生效

当前 Gate 用户提示词经过 `apply_module_layout()`，但 Gate 适配器取得 System 提示词后直接追加 Gate 约束，没有完整采用上游新版“先应用模块布局，再追加管理员覆盖层”的顺序。

风险：控制台修改的 System 模块可能没有按页面展示的布局完整进入模型，或者管理员覆盖层被布局处理丢失。

### 2.6 当前大型模块仍有维护压力

当前主要文件规模：

| 文件 | 当前 Gate | 上游 v7.9.5 |
|---|---:|---:|
| `scripts/ai_brain_trader.py` | 约 1184 行 | 约 830 行门面，并拆成 `scripts/brain/` 子模块 |
| `scripts/ai_factor_trader.py` | 约 1979 行 | 约 1012 行，并抽离职责模块 |
| `r20_backend/app.py` | 约 2770 行 | 约 244 行，路由按域拆分 |
| 测试文件 | 6 | 213 |
| 测试用例 | 约 132 | 约 2943 |

上游重构提高了可测试性和职责边界，但不能仅凭行数判断交易安全，也不能直接覆盖当前 Gate 的专用执行层。

## 4. 当前 Gate 与上游提示词差异

### 4.1 持仓锁盈节奏

| 条件 | 当前 Gate | 上游 v7.9.5 |
|---|---|---|
| 第一次保本移损 | `0.8R` 或 ROI `1.5%` | `1.5R` 且 ROI `2.2%` |
| 第二次锁盈 | `1.5R` 或 ROI `3.0%`，锁约 `0.6R` | `2.2R` 且 ROI `3.5%`，锁约 `1.0R` |
| 峰值回撤退出 | 峰值 `2.5%/1R` 后回撤 `35%~45%` | 峰值 `3.5%/1.8R` 后回撤 `45%~55%` |
| 动能耗散退出 | ROI `1.5%`，`Phi < -0.12` 或曲率 `>=1.5` | ROI `2.5%`，`Phi < -0.15` 且曲率 `>=1.8` |

当前 Gate 更早保护利润，但可能在正常回踩中提前退出并增加手续费；上游更偏向让趋势波段运行，容忍更大回撤。

### 4.2 风控参数来源

- 当前 Gate：旧模板固定数值 + Gate 动态约束附加层。
- 上游 v7.9.5：静态 System Prompt 不再保存资金绝对值，每轮从执行层同一事实源生成“本周期风险预算”。

上游方式更能保证“模型看到的限制”和“执行器实际使用的限制”一致。

### 4.3 Gate 独有输出契约

当前 Gate 额外拥有：

- `entry_intent=immediate|retracement|breakout`。
- Gate GTC、IOC 和原生 `price_orders` 映射。
- 固定执行杠杆和当前风险档位。
- 当前保证金占用、总保证金和单笔保证金上限。
- 突破计划单有效期与滑点硬限制。

这些属于 Gate 执行协议，必须保留。上游新版不能直接替换它们。

### 4.4 决策完整性

上游新版允许 `decisions` 只包含“有明确结论”的标的。当前 Gate 的异常审计要求每轮覆盖完整六合约，否则报告“六合约决策不完整”。

整合时必须先统一契约。建议 Gate 继续要求全部交易池标的均有显式结论，包括 `WAIT`，以便判断整轮是否完整。

8. 全部离线测试、编译和前端构建通过。
9. VPS 部署必须经过用户另行确认。
10. 不以“上游版本更新”作为直接覆盖生产系统的理由。

## 11. 当前建议结论

上游 v7.9.5 的模块化、提示词一致性和测试体系优于当前 Gate 的复用层；当前 Gate 的原生订单状态机、客户端订单号恢复、保护覆盖和环境隔离优于上游通用执行链。

后续目标应是：**吸收上游策略内核和工程质量改进，保留并强化当前 Gate 原生执行外壳。**
