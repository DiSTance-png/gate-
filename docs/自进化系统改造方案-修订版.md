# Gate 自进化系统改造方案（修订版）

## 0. 方案定位

目标是建立一条可审计、可回滚、默认不影响交易执行的自进化链：

```text
交易证据采集
  -> 主机侧证据质量审计
  -> LLM 复盘
  -> 输出规范化
  -> 候选变更生成
  -> 人工审核
  -> 原子安全合并
  -> 只注入已发布长期记忆
  -> 后续周期验证
```

本方案只改造自进化和审计链，不改变 Gate API 执行、Live/Testnet 隔离、止盈止损、风控限制、写锁、fail-closed 和持仓保护。

但是必须明确：长期记忆会进入交易提示词，因此它虽然不是硬风控，也会间接影响 AI 决策。所有发布必须经过人工审核，禁止模型自动改写生产提示词。

本阶段只做本地代码和离线测试。GitHub 推送、VPS 部署、服务重启和任何交易操作均需另行确认。

## 1. 不可违反的安全原则

1. 结构化 JSON 是唯一权威；Markdown 只能是派生镜像。
2. 缺少证据不得补写、推断或伪造历史指标。
3. `NO_CHANGE`、证据不足、解析失败、LLM 失败和发布失败必须显示为不同状态。
4. 未被模型提及的旧规则不得自动删除或停用。
5. baseline 规则永远不能被模型删除、修改或覆盖。
6. 发布失败时，旧记忆、策略参数和资产倍数必须保持字节级不变。
7. 长期记忆发布与资产倍数、风险参数发布必须完全分离审批。
8. 自进化失败不得阻断正常交易；交易执行失败也不得触发自动记忆发布。
9. 自进化模块不得创建、撤销、修改或平仓任何 Gate 订单。
10. 任何网络超时不得重发交易请求；本方案只读审计，不改变订单重试规则。

## 2. P0：输出规范化和发布安全

### 2.1 统一模型输出规范化

修改 `scripts/self_improvement_engine.py`，增加唯一入口 `normalize_evolution_response(raw)`，支持：

- 字典；
- 列表；
- JSON 字符串；
- Markdown 代码围栏包裹的 JSON；
- `evolution_actions`、`ai_long_term_memory` 的嵌套对象；
- 空值、非法类型和重复项目。

规范化结果必须包含：

```json
{
  "diagnosis_insights": [],
  "evolution_actions": [],
  "memory_operations": [],
  "change_status": "NO_CHANGE",
  "raw_proposal_count": 0,
  "normalized_proposal_count": 0,
  "dropped_proposal_count": 0,
  "drop_reasons": []
}
```

普通诊断只能进入 `diagnosis_insights`，不得因为字段名称相似而进入长期记忆。

### 2.2 长期记忆使用结构化操作

禁止只保存扁平的 `proposed_memory` 文本列表。候选必须保存操作对象：

```json
{
  "action": "ADD",
  "target_id": "",
  "rule_text": "可执行且可验证的规则",
  "evidence_refs": ["gate_closed_xxx"],
  "evidence_summary": "多个独立样本支持该结论",
  "confidence": 0.72,
  "scope": "适用的市场状态",
  "reason": "为什么新增或修改"
}
```

允许的操作只有：

- `ADD`：新增规则；
- `REVISE`：按 `target_id` 修改非 baseline 规则；
- `INVALIDATE`：停用非 baseline 规则但保留历史；
- `NO_CHANGE`：不改变任何规则；
- `COLLECT_EVIDENCE`：只提出数据采集建议，不产生发布候选。

### 2.3 原子合并规则

修改 `scripts/evolution_shield.py`：

- 合并以旧版本快照为基准；
- `ADD` 追加，不覆盖旧规则；
- `REVISE` 只能命中明确的非 baseline `target_id`；
- `INVALIDATE` 只将规则设为停用，不能物理删除；
- 未提及的启用规则原样保留；
- baseline 原样保留；
- 版本号不匹配时拒绝发布；
- 发布前完成全部校验，发布时一次性原子替换；
- 失败时恢复旧文件，并验证恢复后的版本哈希。

候选应用接口必须同时接收 `expected_memory_version` 和候选版本，不能使用当前版本自动覆盖冲突。

### 2.4 记忆发布和参数发布分离

`apply_evolution_candidate()` 不得因为应用记忆候选而自动写入 `asset_multipliers.json`。

如果保留资产倍数建议，必须生成独立的 `parameter_candidate`，使用独立审批按钮、独立版本号和独立测试。默认只允许发布长期记忆。

## 3. P0：状态和失败原因

每轮报告增加：

```json
{
  "memory_state": "ready",
  "publication_status": "not_requested",
  "publication_error": "",
  "memory_preserved": true,
  "baseline_available": true,
  "raw_proposal_count": 0,
  "normalized_proposal_count": 0,
  "dropped_proposal_count": 0,
  "drop_reasons": []
}
```

状态统一为：

- `COLD_START`：尚未初始化权威记忆；
- `NO_CHANGE`：复盘完成且没有可靠变更；
- `INSUFFICIENT_EVIDENCE`：有分析但证据不足；
- `WAITING_REVIEW`：已生成候选，等待人工审核；
- `PUBLISHED`：人工审核后成功发布；
- `LLM_ERROR`：模型调用失败；
- `PARSE_ERROR`：模型响应无法规范化；
- `PUBLICATION_ERROR`：候选发布失败；
- `CONFLICT`：记忆版本冲突。

这些状态必须同时写入 JSON 报告、审计日志和控制台接口，不能只写一条普通日志。

## 4. P1：结构化记忆初始化和镜像

增加管理员显式初始化流程：

1. 检查 `structured_trading_memory.json` 是否存在且通过校验；
2. 首次初始化时写入 baseline 规则、schema 版本、revision 和创建时间；
3. 同步生成 `AI_TRADING_MEMORY.md`；
4. 初始化完成后才允许候选发布；
5. 缺少权威文件时显示 `COLD_START`，不能把旧 Markdown 当成已发布权威；
6. 旧 Markdown 只允许只读兼容，不得自动迁移覆盖结构化文件。

Markdown 每次由结构化文件重新生成，禁止手工内容成为第二数据源。

## 5. P1：交易证据和证据质量

### 5.1 入口证据

继续使用现有 `entry_snapshot`，并确保新仓位保存：

- 合约、方向、时间、入场价格；
- 4H 趋势、1H 结构、regime；
- velocity、acceleration、jerk、impulse；
- energy/deviation、延续/击穿概率；
- ATR、R:R、VaR/CVaR；
- 风控快照、策略版本、policy hash；
- 原始 AI 信号和执行意图。

### 5.2 出口证据

尽量从 Gate position close 和成交账单读取：

- 平仓时间和原因；
- 真实开平仓价格；
- 实际手续费、资金费、滑点；
- 持仓时长；
- MFE、MAE；
- 毛盈亏和净盈亏。

无法从 Gate 或本地记录证明的数据必须为 `null`，禁止用当前行情或后续行情回填历史快照。

### 5.3 证据质量分类

每笔交易只能被宿主程序分类为：

- `OBSERVED`：入口和出口证据完整；
- `PARTIAL`：部分关键字段存在；
- `PRICE_ONLY`：只有价格和盈亏；
- `UNAVAILABLE`：没有可关联的有效快照。

LLM 只能使用宿主程序计算的分类和统计，不得自行统计证据覆盖率。

## 6. P1：主机侧可观测性

新增 `scripts/evolution/observability.py` 或同等模块，主机程序计算：

- 总平仓样本数；
- `OBSERVED/PARTIAL/PRICE_ONLY/UNAVAILABLE` 数量和占比；
- 可用于因果判断的有效样本数；
- 缺失的具体字段；
- 证据周期和 ledger revision。

示例注入内容：

```text
本周期平仓样本：20
完整入口出口证据：11
部分证据：5
只有价格数据：3
无可关联快照：1
可用于因果判断的有效样本：11
不得对缺失证据做因果结论。
```

LLM 的每条长期记忆必须引用 `evidence_refs`，且引用的样本必须满足最低证据质量和样本量要求。总交易数不能代替该规则自己的有效样本数。

## 7. P1：提示词和候选规则

提示词必须明确区分：

- 已验证事实；
- 待验证假设；
- 数据采集建议；
- 长期规则候选。

长期规则候选至少需要：

- 两个或以上独立样本；
- 明确适用范围；
- 正例和反例检查；
- 不触碰硬风控；
- 不扩大止损、不取消保证金限制、不改变 Live/Testnet 逻辑；
- 可通过后续数据验证。

单笔交易、单一极端行情、缺少入口快照或只依赖最终盈亏的结论，只能成为诊断或 `COLLECT_EVIDENCE`，不能成为长期记忆。

## 8. P2：后台和历史展示

控制台自进化页面应显示：

- 当前权威记忆版本和哈希；
- baseline 数量和状态；
- 候选的操作类型、目标规则、证据引用和丢弃原因；
- 发布状态和失败原因；
- 证据覆盖率；
- 记忆应用前后差异；
- 回滚入口及目标版本。

现有最近 200 轮摘要可以继续保留作为快速视图；完整历史从审计 JSONL 或归档文件分页读取，不改变现有交易接口。

## 9. 测试要求

### 9.1 输出规范化

- 字符串、字典、列表、JSON 字符串均能规范化；
- 嵌套 `ADD_MEMORY` 能转为结构化 `ADD`；
- 普通 `COLLECT_EVIDENCE` 不得进入长期记忆；
- 非法对象不会生成 `[object Object]`；
- 丢弃数量和原因准确记录。

### 9.2 记忆安全

- 空候选不清空旧记忆；
- `NO_CHANGE` 完整保留旧规则；
- 未提及的启用规则仍然存在；
- baseline 不能修改、删除或停用；
- `REVISE` 只影响目标规则；
- `INVALIDATE` 只停用并保留历史；
- 版本冲突拒绝发布；
- 发布失败旧文件哈希不变；
- 应用记忆候选不会修改资产倍数；
- 并发发布只有一个版本成功。

### 9.3 证据审计

- 完整、部分、只有价格、无快照四类识别正确；
- 缺失字段保持 `null`；
- 不会用当前行情补写历史指标；
- 每条候选规则都有有效证据引用。

### 9.4 运维和交易隔离

- 自进化失败不影响交易执行；
- 自进化测试不访问真实下单接口；
- 不修改 Live 配置；
- 不修改当前持仓和保护单；
- 不会自动应用历史候选；
- 不会自动重启 VPS 服务。

## 10. 执行和发布顺序

1. 只修改本地 P0 代码和测试；
2. 本地运行 pytest、compileall、`git diff --check` 和前端构建；
3. 进行只读样例复盘，确认报告状态和候选内容；
4. 展示文件变更、测试结果和安全检查结果；
5. 用户确认后再推送 GitHub；
6. 用户再次确认后才部署 VPS；
7. VPS 部署前备份代码和数据，检查持仓、保护覆盖和写锁；
8. 先 dry-run 自进化，再决定是否重启服务；
9. 至少观察一个完整证据周期后，才评估是否需要调整提示词。

## 11. 验收标准

只有同时满足以下条件才算完成：

- 新格式模型输出可以稳定生成结构化候选；
- 普通诊断不会注入长期记忆；
- 未提及旧规则不会消失；
- baseline 永远不能被删除或停用；
- REVISE/INVALIDATE 具有明确目标和审计记录；
- 记忆发布不改变资产倍数和交易参数；
- 证据缺失会明确显示并阻止过度归因；
- 解析失败、证据不足和 NO_CHANGE 可区分；
- 发布失败时旧记忆哈希不变；
- Markdown 与结构化权威一致；
- 自进化故障不影响 Gate 交易执行；
- 全部离线测试通过；
- 本地验证期间没有新增订单、撤单、平仓或 Live 配置变更。
