# 盈利回吐保护方案：评审后修订

日期：2026-10-29。版本：v2 修订附录。状态：仅方案，未实现、未部署、未激活。

配套文件：`盈利回吐保护改造方案-待审核.md`（v1 原文保持不变）、`盈利回吐保护方案-子智能体评审.md`。

独立子智能体对 v1 评分 82/100，结论为“有条件进入本地实现，实盘激活不通过”。本附录回应评审问题，不代表子智能体已对 v2 重新评分。冲突处以本附录为准。

## 1. 第一阶段仅接管单一风险段

第一阶段只管理同时满足以下条件的持仓：

1. 初始入场订单已达到可证明的终态，不再存在未成交余量、待触发单或歧义执行意图。
2. 已确认真实最终成交均价 E、数量 q0 和初始实际止损 S0；D0 = |E - S0| > 0，确认原生 TP/SL 完整覆盖。
3. 系统能把实际持仓唯一对应到环境、账户、方向和本次持仓周期；无加仓或无法归属的外部仓位。
4. 方向对应的可替换系统止损唯一，所有权、reduce_only/close/auto_size 和覆盖数量均经确认。

入场部分成交但仍可能继续成交时，只由现有执行器补齐保护，guardian 不接管。订单结束后，按最终实际均价和保护确认冻结一个整仓初始风险段，不将每次 fill 各自的峰值直接合并为整仓止损。

加仓、来源不明数量变化、双向歧义立即使该仓退出 guardian 自动修改范围，保留当前原生保护和已完成阶段；不能把历史峰值用于新增部分。后续分段合并另行设计。覆盖报告同时列出已覆盖/未覆盖的持仓数、初始风险金额、名义敞口和跳过原因，不能只展示成功案例。

试验组不加仓属于待审核的研究设置，不在本轮修改现行加仓配置。

## 2. 修正部分减仓后的成本计算

固定的是 E、S0 和价格风险距离 D0；保留初始 q0 用于历史审计，但不能用于剩余仓位成本换算。

- 初始风险金额：R_initial = |q0| × multiplier × D0。
- 当前剩余风险金额：R_remaining = |q_remaining| × multiplier × D0。
- 剩余成本预算：C_remaining，包含归属剩余仓位的开仓费、预计平仓费、已发生的资金费支出和滑点预算。
- 成本保本 R 位置：c_R = C_remaining / R_remaining。
- 等价价差：cost_distance = C_remaining / (|q_remaining| × multiplier)。
- 多头保本价 E + cost_distance；空头 E - cost_distance。真实成交仍可能受滑点等影响，不能保证净零亏损。

例：初始 10 单位、D0 = 10、乘数为 1，R_initial = 100；减至 5 单位后 R_remaining = 50。若剩余成本为 5，c_R = 0.1，需要价格有利移动 1，毛利润 5 才能覆盖成本；不能用原分母 100 算成仅移动 0.5。

部分减仓只在外部/现有系统动作及台账都已确认、成本归属清晰时更新 q_remaining；不改变 E、D0 和峰值。剩余 q 为零则关闭周期。已实现盈亏独立记账，不重复抵扣剩余成本。费用不清晰时跳过成本保本，显示原因；价格减亏阶段可在其他条件完整时继续，但不能标成净保本。

## 3. 止损替换与持续歧义决策表

### 3.1 实现和启用前的硬条件

先确认当前 Gate 账户模式和保护类型能否原位修改，核验官方契约并在隔离 Testnet 证明其保留保护语义；不能把未知 API 能力写成实现前提。

不能原位修改时，只实现 observe 和离线替换状态机，直到撤旧建新协议通过独立执行安全门。增加实盘撤建频率不属于可先试再补的工作。

状态机由独立恢复通道负责；停用策略计算也不能停用 pending 意图恢复。每个意图固化持仓周期、数量上界、方向、旧新单身份和修订，完整重读后再动作。

### 3.2 查询顺序与终态证据

1. 按新 client_id 和已知 order_id 查询开放保护单。
2. 查询提交时间窗口内的已结束/触发/取消保护单，按交易所实际分页规则遍历，并用客户端身份精确匹配。
3. 如保护单已触发，按其 trade_id/订单身份核对触发后的普通订单与实际成交。
4. 同步核对当前持仓周期、实际剩余数量和所有匹配的原生保护。

结果未找到、API 超时、未完成分页均不构成明确拒绝。查询适配器未覆盖当前模式的终态语义时，禁止 enforce。交易所明确拒绝或精确身份查询得到可信终态，才可以判定对应提交不再可能成为活动保护。

### 3.3 时间预算与决策

时间均从“旧止损撤销已确认”开始计算。以下是待测的执行预算，不是对断网时交易所结果的保证：正常替换目标 3 秒内确认；超过 3 秒标 degraded；10 秒仍不明必须升级应急处理。需按账户 API 时延验证，不通过则不上线撤建方案。

| 真实状态 | 动作 |
|---|---|
| 旧单仍在，撤销不明 | 保留并核查，不再创建新单；阻断进一步修改与新增风险 |
| 新单存在且覆盖正确 | 记为已确认，核对旧单终态及整仓 TP/SL，提交 COMPLETE |
| 新保护已触发/已成交 | 核对成交及剩余仓位；不恢复旧单，不重复平仓 |
| 新单明确失败，旧止损价仍合法 | 使用唯一恢复意图恢复旧止损，确认覆盖；失败继续升级 |
| 已无持仓或周期已变化 | 归档/人工复核；旧周期意图不得作用于新仓，不盲目清理来源不明保护 |
| 新单持续不明、原仓仍可证明存在 | 不再盲目创建保护；启动经单独授权的 reduce_only 应急处置，严格限制在该周期可归属的剩余数量 |
| 网络完全不可用或仓位身份无法证明 | 标记 critical、阻断新增风险、保留全部事实并告警；无法承诺已恢复保护或已平仓，等待可验证对账 |

应急处置采用持久化唯一 close_client_id；新单即使晚到，也只能是同周期 reduce_only 保护，不能加仓。应急退出仍须核实旧周期未变、最新归属数量和是否已有关闭请求在途；关闭超时先查既有身份，不换 ID 重复发送。无法证明不影响新周期时不自动关闭。

应急处置权限须作为用户审核的 enforce 策略的一部分，明确允许范围；尚未授权或不能证明账户模式下只减当前系统份额，不能启用需要依赖该应急路径的撤建方案。网络分区下不存在软件保证的“有界交易完成”，应急时限只约束本地升级和可用连接下的尝试。

隔离 Testnet 验收包含正常空窗分布、每种失败注入和断网残余风险；不能用只读 shadow 的 0 写请求证明替换安全。

## 4. guardian 死亡时，入场链路也必须关门

guardian 不能负责证明自己的健康。新增统一的本地 guard 准入检查函数，由所有新增风险请求在共用 Gate 写锁内直接调用：自动开仓、加仓、Web 手动开仓/加仓、突破计划提交、入场挂单 AMEND 重建及其他扩大风险路径。

- enforce 模式要求存在最近一次成功完整检查，时间不超过 30 秒，环境、账户、策略哈希、进程 epoch 和持仓修订相符；未来时间戳及异常时钟也不能当作健康。
- 有未闭环保护修改、关键错误、状态读取损坏或不一致时 fail-closed，不能仅靠页面 safety_status 缓存或定时告警拦截。
- observe 不因 guardian 没有 enforce 心跳阻止现行交易；但任何模式下已存在的保护修改 pending 意图仍必须进入执行安全门，切换 observe 不消除它。
- 独立 watchdog 用于心跳/告警/恢复调度；guardian 的独立执行槽不能依赖 trader 完成，也不能因 LLM 占满线程池失去调度。
- 平仓、合法收紧保护和恢复对账不被“禁止新增风险”拦住。
- 刷新/Web 聚合/进程重启都使用同一权威准入状态，不能覆盖或丢失 guard 阻断原因。

心跳过期只能阻止未来新请求，不能保证已挂在 Gate 的入场单不再成交。已有入场计划纳入预留风险；发现 guard degraded 时，由已授权的入场生命周期流程尽力取消可确认系统来源的剩余入场单，并对部分成交补齐保护。取消不明则继续阻断，断网时明确记录原生待触发风险。不能宣称本地关门等于交易所已停止所有入场。

测试需包含 kill、hang、调度槽饥饿、missing/future timestamp、策略版本变化、账户/环境错配、pending 修改、observe/enforce 切换和已挂入场单的延迟成交。

## 5. 三道门与实施拆分

### 5.1 工程门：可以先实现，不依赖 A/B 获利

C1a：固定 D0、单一风险段、正确成本分母、持久化和纯函数；只读采样。

C1b：独立调度与心跳消费、移损状态机、终态查询、保护生命周期和所有写路径准入；本地故障测试。

C1c：隔离 Testnet 验证原位修改或替换/恢复路径。未通过则 enforce 不可用，保留 observe；不能用“工程实现完成”代替执行验证。

### 5.2 数据门：样本与执行能力分别报告

最低 30 个独立持仓周期、4 个周窗口只是进入效果评估的必要条件，不代表样本独立或区间可靠。10-29 已用于提出参数，不计作未调参验证。

shadow 至少 7 个完整自然日，验证采样、价格可用性、可挂目标、延迟和禁止写请求；P95 检查间隔目标 <= 15 秒。真实保护替换空窗、恢复和重复写指标只在 Testnet enforce 故障验证中验收，不能由 shadow 替代。

历史缺少完整事件数据时只作固定入场研究，前向观察继续积累，不构造完整组合收益。

### 5.3 效果门：冻结判据后比较，不事后扫参数

- 保留 C0/C1/A/B 对照，A/B 数值不因看到今天的回放结果再调整；若提出第三组，新建研究版本和未使用验证集。
- 配对比较按同一入场序列计算候选相对 C1 的每日净收益差；同日全部相关币种在同一区块。固定使用连续 7 个自然日的移动区块、10,000 次重采样及预先保存的随机种子，不将交易随机拆散。
- 对 A、B 两次选择使用 Bonferroni 校正：各自报告 97.5% 双侧区间，使两组比较的联合覆盖目标至少 95%。区间下界必须 > 0 才满足预定改善门。
- 只有 4 周数据时仅约 4 个周长度区块，重采样可能不稳定。必须报告有效区块数、分布/结构变化及区间局限；不能因得到狭窄区间自动宣称可信。独立未调参验证段也要分别同向改善，跨币组结果不得由单一异常赢家支撑；证据仍不足就保持研究状态。
- 费用、资金费、保守成交顺序和滑点全部计入；候选扣费收益为正、最大回撤不劣于 C1、双倍成本/滑点压力下不出现负期望。满足这些必要条件也不能等同已证明未来盈利。
- 最终提交用户的报告列出全部比较、收益分布、回撤、大盈利被提前扫出的损失、覆盖/未覆盖敞口、执行失败和不确定性；参数进入实盘仍由用户最后审核。
