## 必须保留的限制

1. v4 不能把 92 分解释为盈利概率；S1 的 `-0.25R0`、S2 的成本保本和 S3 的 `0.50×MFE` 仍是待验证参数。
2. C1a 只能纯计算和持久化，不能写 Gate 保护单；C1b 需先有独立 heartbeat 消费和所有新增风险写前准入；C1c 需 Testnet 证明保护修改/恢复语义。
3. 单一风险段边界必须硬编码：加仓、部分成交未终态、外部数量变化、双向歧义和来源不明保护单均 `UNMANAGED`，不自动接管。
4. 现有 `risk_profiles.py` 仍以当前 stop 计算 R，现有 `ai_worker.py` 管理路径依赖 LLM 成功，当前 scheduler 使 trader 与 execution reconcile 互斥；这些是 C1a/C1b 的实际实现任务，当前代码尚未达到方案状态。
5. 所有方案评分达到 90 也不替代用户对实际 S1～S3 参数、回放报告和 enforce 开关的审核。

## 是否可执行

- **进入本地实现：是，有条件。** 只实现 C1a 纯计算、数据库状态、observe 采样和测试；不得先写交易所。
