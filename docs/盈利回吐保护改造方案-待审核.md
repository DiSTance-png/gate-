# 盈利回吐保护改造方案（待审核）

版本：v1，2026-10-29。状态：仅方案，未实现、未启用。代码核查基线：7e4d96f。

## 0. 本轮工作约定

- 目标：针对持仓曾经浮盈、随后回撤到原始止损的问题，提出可实现、可验证的退出管理改造，并由一名独立子智能体评分。
- 模式：方案与评审。只读检查本地代码，写入本方案和评审文档。
- 范围：已有持仓的盈利保护、保护单执行恢复、研究验证、人工审核界面。
- 边界：本轮不改运行代码、不提交或部署、不调用交易写接口、不应用策略候选。
- 参数均为研究假设；收益改善须经扣费回放与前向观察验证，技术修复不等于策略已盈利。
- 检查点：初稿完成后交独立子智能体审查；保留其原始分数、问题与否决项，修订另记，不自行替其提高分数。
- 验收：说明证据限制、数学定义、状态恢复、失败处理、验证门槛；只交付方案和评审，不以修改实盘作为完成条件。

## 1. 已确认问题与证据边界

### 1.1 代码事实

1. `gate_quant/risk_profiles.py::derive_profit_lock_instruction` 用当前保护止损计算 initial_risk。移损后 R 分母改变，移至保本或盈利区后 initial_risk <= 0，会提前返回，影响后续锁盈。
2. `gate_quant/ai_worker.py` 在 15 分钟决策中追加确定性保护；管理执行仍要求 `llm_source == gate-multifactor-llm`，模型调用失败会使该保护分支无法执行。
3. 模型已输出 UPDATE_SL 时，会跳过确定性建议；这可能使一个较弱或不合法的模型指令遮挡更严格的规则。
4. `r20_gateway/scheduler.py` 将 trader 与 execution_reconcile 整个任务互斥。模型等待期间，10 秒对账不等于每 10 秒必然完成保护。
5. `execution_reconciler.run_once()` 没有活动入场意图就提前 idle；不能直接用它证明已完成开仓的所有持仓均获持续盈利管理。
6. 当前激进档执行保本阈值为 1R。模型预算还描述 ROI 触发，但确定性函数实际只按 R 执行，数值含义需统一。
7. `GateTradingService.replace_stop_loss_safely` 当前采用撤旧止损、创建新止损、失败恢复的链路。其间存在保护空窗；超时后创建结果不明时，不能直接再建恢复单。必须审计和加固后才能增加移损频率。

### 1.2 历史观察不能当作已验证收益

此前只读核查 2026-10-29 已平仓行，得到 11 笔、3 盈 8 亏、净 -61.96845682 USDT；这是当时快照，不是当前动态账户状态。

持仓区间内完整 1 分钟成交价 K 线显示，部分亏损单曾有约 0.34R、0.57R、0.46R 的有利波动。这些例子提示 1R 门槛可能过晚，但不能证明每笔都应盈利或更早移损必然改善总收益。

- 成交价极值不等于止损触发价格、标记价极值或可成交买卖价。
- 开平仓所在的首尾分钟被保守排除，分钟内先后顺序仍不确定。
- 没有完整初始风险、仓位归属或加仓链的样本，不可强行计算准确 R。
- 必须同时评估盈利单，防止把原本的大盈利提前扫出后，胜率提高但总收益下降。

## 2. 第一阶段范围

先改退出保护；开仓信号、入场 R:R 下限、TP 目标、杠杆、保证金上限、组合限制与日亏损熔断保持现状，便于识别改动效果。

第一阶段不加入分批止盈、不提高仓位、不自动重置熔断、不改自进化发布证据门。分批止盈与自进化研究门修改如有需要，另做方案、单独审核。

## 3. 固定风险单位与持仓身份

新建纯计算模块 `gate_quant/profit_guard.py`，运行模块 `gate_quant/profit_guard_worker.py`；计算模块不接触交易所。

### 3.1 不可变初始风险

首次实际成交并确认初始保护后固化：

- E：实际成交成本；S0：基于真实成交确认的初始止损价格；D0 = |E - S0| > 0。
- q：该风险段真实成交张数；乘以 Gate 合约乘数得到基础资产数量。
- R0_USDT = |q| × 合约乘数 × D0。此处 R0 为毛风险，手续费另算。
- s：多头 +1，空头 -1；r(t) = s × (P(t) - E) / D0。
- m(t) = max(0, 所有已可靠观测的 r)。保留观测来源与时间；它只是采样峰值，不冒充真实逐笔峰值。

S0、D0 不随移损改变。初始阶段已部分成交时按真实成交建立独立风险段，后续成交扩仓先补齐保护，再更新归属；不能重用旧峰值保护新成交。

身份键包含环境、账户指纹、结算币、合约、方向、position_cycle_id、fill_segment_id，防止空仓重开和 Live/Testnet 串用峰值。

### 3.2 已有持仓、减仓和加仓

- 已有持仓只从可证明匹配的执行事件、真实成交和初始保护恢复。恢复不了：保留 Gate 保护，标记 unmanaged_initial_risk，不猜测 D0、不自动接管。
- 同周期部分减仓：保留 E、D0、峰值与历史阶段，按实际剩余数量确认保护；完全平仓归档，下一次开仓使用新周期。
- 加仓会改变均价，不能直接沿用旧 E 或把峰值清零。第一阶段对已加仓、外部数量变化或无法证明归属的仓位，暂停新 guard 移损，保留已有保护并交现有对账流程处理，明确记录未覆盖范围。
- 启用早保护的试验仓位采用“不加仓”研究分组；若用户仍保留现行加仓行为，则该组不纳入策略改善结论，待独立分段合并设计后扩展。
- 双向持仓未能唯一识别方向及对应保护时不修改；人工、未知来源保护单不自动撤销。

## 4. 两组待测参数与明确规则

所有参数先离线比较，不预设任一组可直接用于实盘。

| 方案 | 采样峰值达到后开始减亏 | 减亏后止损位置 | 开始成本保本 | 开始峰值跟踪 | 峰值至少保留比例 |
|---|---:|---:|---:|---:|---:|
| C0 当前策略 | 当前逻辑 | 当前逻辑 | 激进档 1.0R | 当前逻辑 | 当前逻辑 |
| C1 仅工程修复 | 不新增 | 不新增 | 维持现有档位 R 门槛 | 维持现有 R 锁盈档位 | 不新增 |
| A 较早保护 | 0.35R | -0.50R | 0.55R | 0.80R | 50% |
| B 较宽保护 | 0.50R | -0.50R | 0.75R | 1.00R | 50% |

C1 指固定 D0、调度独立、模型故障不影响保护等修复；ROI 与 R 的策略触发口径先保留实际执行 R 规则并修正文案，不能顺手新增 ROI 自动触发。

“减亏”只减少计划损失，例如允许亏损从 1R 降到 0.5R，并非已锁定盈利。A 也无法覆盖峰值仅 0.34R 的 ETH 示例，不宣称救回所有亏损单。

### 4.1 扣费后的保本位置

以剩余仓位计算成本 C：可归属的开仓手续费 + 预计平仓 taker 手续费 + 已发生的净资金费支出 + 滑点预算。第一阶段不把资金费收入当成可消费的保护空间；平仓时点以外的未来资金费不保证覆盖。

c_R = C / R0_USDT；多头成本保本价格 E + c_R × D0，空头 E - c_R × D0。减仓后的成本归属必须可审计，避免把已实现利润重复计入。

成本不可靠时不标记“净保本”；跳过成本保本阶段，保留原保护并告警。保本价是预算目标，跳空、流动性和滑点仍可能造成实际净亏损。

### 4.2 阶段、峰值和止损合并

1. 峰值不足第一门槛：保持原止损。
2. 达减亏门槛：候选止损收益位置为 -0.50R。
3. 达成本保本门槛：候选位置至少为 c_R。
4. 达峰值跟踪门槛：候选位置至少为 max(c_R, 0.5 × m)。例如峰值 0.8R 时计划保留约 0.4R 毛收益，并比较成本底线。
5. 多头取所有合法候选中的最高止损，空头取最低止损。已确认的止损不得放宽；AI HOLD 不遮挡 guard，AI 移损与 guard 选择更严格且合法者，AI 平仓先确认结果。

只有峰值够大且当前价格仍允许挂出该目标时，才能推进；不按事后历史最高价倒填阶段。

### 4.3 价格和频率约束

- 用对应 Gate 原生保护单的真实 price_type、trigger rule 判断；明确区分成交价、标记价、指数价。不能用标记价判定合法，却创建成交价触发的止损。
- 同时检查最新可成交买卖价、价差、价格步长及数据时间；价格超过 15 秒未更新或私有查询失败则不撤旧保护。
- 多头止损向上取整、空头向下取整后重新检查；至少保留 max(2 ticks, 当前价差) 的触发距离。取整使几何失效时跳过，不放宽旧止损。
- 首次减亏/保本阶段允许下一次有效检查立即执行。普通连续跟踪要求比当前止损至少改善 max(2 ticks, 0.05D0)，并距上次已确认更新至少 60 秒；更高阶段首次晋级可越过 60 秒节流。
- 本地峰值刚被观测到时如新止损已被价格穿越：记录 MISSED_PROTECTION，保留旧止损，不创建无效止损、不自动补发市价平仓；计入策略失败样本。是否新增这种情况下的立即退出，须另列候选审核。
- 没有本地连接时 Gate 已确认的 TP/SL 继续生效，但本地跟踪不会实时推进，不能宣传“绝不回吐”。

## 5. 独立执行与可恢复状态机

### 5.1 调度

- 独立 guardian 每 10 秒尝试检查已归属持仓，有独立单执行槽，不占用模型线程池；不因没有活动入场意图而 idle。
- trader 的模型请求和提示词计算不持有 Gate 写锁；移除以整个任务为粒度的阻塞，所有 Gate 写路径仍在既有共用写锁中串行。
- 写前在锁内重新查询持仓、成本、保护覆盖和价格，比较 expected_position_revision 和阶段；外部变化则放弃本轮，重新对账。
- 锁竞争短等待后记 busy，不盲目重试订单。10 秒是目标检查间隔，记录真实间隔、锁等待与 API 时延；连续超过 30 秒未完成成功检查标为 degraded，并关闭新增风险，保留原保护和独立恢复对账。
- 日亏损熔断不阻止已持仓合法收紧保护；新增交易开关关闭不等于自动开启 guard 写能力。使用独立的 `observe` / `enforce` 模式，默认 observe，进入 enforce 必须审核策略版本与明确授权。

### 5.2 持久化

在已有执行数据库中增设按环境隔离的 guard 状态和修改意图表，迁移必须增量、可回退，不删历史记录。

状态记录 E、S0、D0、真实数量、峰值、峰值时间、价格来源、成本口径、候选阶段、已确认阶段、已确认止损、策略哈希、持仓修订号、心跳与失败原因。

每次修改先持久化唯一 intent_id/client_id、old_order_id、旧新目标、期望数量与修订号，再调用交易所；候选阶段与已确认阶段分开，不能先写“保本成功”再发请求。

### 5.3 移损协议

建议状态：PREPARED → OLD_CANCEL_CONFIRMED → NEW_SUBMITTED → NEW_CONFIRMED → COMPLETE；异常进入 RECONCILE_REQUIRED / RESTORE_PENDING / MANUAL_REVIEW。

- 实现前核对 Gate 当前账户模式的原位修改能力。若可用且验证通过，优先原位修改；不能假定原生 API 支持无空窗替换。
- 若仍需撤旧建新，准确识别系统所有权、方向、reduce_only/close/auto_size 与数量覆盖；先持久化恢复意图，再撤单并确认。
- 创建超时：先按同一 client_id 查新单和持仓，不能直接创建第二个新单或恢复单；查不到不等于交易所已拒绝。
- 只有明确失败或完成可证明的终态对账后才恢复旧单；恢复目标已穿越行情时不能盲目创建，进入现有保护缺口恢复流程，按可证明的系统持仓范围执行已授权的 reduce_only 应急保护并阻断新增风险。
- 崩溃在任一步：重启先恢复 pending 意图，确认真实持仓和保护后才能执行下一次移损。市价/保护成交也要按身份查单，禁止重复关闭。
- 部分成交、保护已触发、人工修改、同向加仓、账户模式变化均使原修订失效，重新对账。
- 对账器不得用旧入场 SL 覆盖更紧的 guard 止损；所有系统新 client_id 前缀必须纳入保护生命周期、恢复识别和孤立单审计。未知前缀不能按系统单撤销。
- 移损失败时优先保留/恢复已知保护，不因一次利润保护失败盲目平掉整币仓位。

## 6. 自进化与审核展示

第一阶段增强复盘证据，不更改既有长期记忆发布门：

- 每笔新增最大采样浮盈 MFE_R、最大采样不利波动 MAE_R、净已实现收益、阶段到达与确认时间、利润回吐比例、MISSED_PROTECTION、跳过原因和执行延迟。
- 历史 K 线重建字段使用 `RECONSTRUCTED` 标签，不能伪装成开仓时已观测的 `OBSERVED`，也不混入现有因果证据样本计数。
- “浮盈转亏比例”仅统计峰值毛收益超过完整成本预算的已平仓样本；同时报告全样本和分币种/多空/行情组收益。
- 研究候选 A/B 与现行策略比较；未通过研究门只保留建议，不自动调整门槛、倍率或风险档位。
- 管理页显示参数全文、证据窗口、样本数、成本假设、改善与恶化交易、版本；评分不代替用户审批，旧版本候选不能自动绑定成当前参数候选。

## 7. 验证：先证明执行可靠，再判断策略价值

### 7.1 离线执行测试（启用前全部通过）

- 多空对称、Decimal/步长、成本超过门槛、过期/异常价格、价差扩大、触发价类型一致。
- 固定初始 R；保本后继续推进；更严格 AI 指令合并；模型超时/坏 JSON 时 guardian 正常检查。
- 开仓与部分成交、部分减仓、加仓暂停、同币平仓重开、双向持仓、人工保护、环境/账户隔离。
- 取消不明、创建超时但交易所成功、确认延迟、恢复单失败、每个状态点崩溃重启；不可重复下单、不可放宽止损、不可误平原仓。
- trader/Web/guardian/对账同时操作：锁内重读、互斥写、幂等恢复；模拟模型等待 120 秒，guardian 仍能获得独立调度。
- 节流与限速：不频繁撤建，达到第一阶段无不必要 60 秒延迟；无活动执行意图仍管理持仓。
- 既有全量 pytest、compileall、前端 build、git diff --check 均通过；测试中不得发送真实 Live 请求。

### 7.2 历史回放（可复现，不挑选赢家）

1. 锁定数据快照、成本口径、代码/配置哈希、A/B 参数及验证规则后再运行；2026-10-29 已被用于提出假设，只能视为开发样本，不能当独立验证。
2. 纳入所有能证明开仓和退出的交易，包括盈利单；不可观测交易单列，不用猜测修补。按时间分开发集与尚未用于调参的验证集；同一持仓与同日高相关币种作为组，不随机拆散。
3. 对照 C0（当前真实逻辑）、C1（仅工程修复）、A、B，分别解释收益来自修复还是参数改变；C0 不能用逐分钟理想成交冒充真实 15 分钟执行。
4. 分钟 K 线同一根同时碰到“盈利门槛”和“回撤止损”，不能假定有利顺序；使用逐笔/更细数据，或同时报告悲观/乐观边界，缺少新规则激活顺序则该根不主张可执行利润。
5. 回放按当时可用价格、保护确认延迟、价差、taker 手续费、资金费、滑点、撤建空窗、最小张数和 API 失败建模。不能把最高价卖出当成交。
6. 旧交易在新规则下提前平仓后，后续资金、冷却和入场机会也会变化。第一步只作“固定入场退出研究”，不能称为完整组合收益；完整收益必须事件驱动重跑组合，无法重建时改以前向影子观察验证。
7. 指标：扣费净收益、每笔期望、最大回撤、利润因子、平均盈利/亏损、成本覆盖后浮盈转亏率、大盈利保留、更新次数/保护空窗和失败率。不能只看胜率。

### 7.3 研究与上线门槛

- 最低观察量：至少 30 个独立持仓周期、4 个周窗口的未调参验证/前向样本；只是最低研究门，不代表统计充分。若达不到，交付“证据不足”，不降低门槛凑通过。
- 按天/相关币组做区块重采样，报告候选相对 C1 扣费收益差的不确定区间；若 95% 区间仍跨零，不能声称改善已获验证。只有 A/B 两组，记录两组比较并控制多次选择偏差，不反复扫参数。
- 候选扣费总收益须为正、相对 C1 的收益改善区间下界大于零、最大回撤不高于 C1；双倍滑点和费用预算压力下仍不转为负期望。若收益与回撤取舍不满足此门，列明取舍交用户，不能自行放宽。
- 先 observe 运行至少 7 个完整自然日，比较真实可挂止损、延迟与阶段，不调用任何交易写接口；模拟成交需标清不是实盘收益。
- shadow 阶段 guard 目标间隔 10 秒，实际成功检查 P95 <= 15 秒，超过 30 秒均产生可见 degraded，原生保护缺口与重复写为 0。
- 真实 Gate 替换语义、限速和恢复需要在隔离 Testnet 上验证；Testnet 写回归须符合用户原有授权且不能影响现有仓位。测试网通过不等于实盘收益已验证。
- 实盘激活最后一步由用户审核参数、覆盖范围、成本和验证报告；如要小额试运行，再明确额度/期限，不擅自增加仓位。

## 8. 上线与回退设计（仅计划）

1. 文档/方案审核 → 工程修复与离线故障测试 → 参数回放 → shadow 证据 → Testnet → 用户审核 → 部署默认 observe → 单独激活 enforce。

3. 停用 guard 只停止未来策略移损；已挂出的更紧保护保留，pending 修改意图由恢复通道继续对账。回退不得把止损放宽到旧位置，不删除数据库或未完成意图。
4. 灰度期间风险改变、频繁过早止损、真实收益偏离预算或执行 degraded：记录完整事实并停止新策略扩围；新增风险按照安全状态关闭，已有保护继续有效。
