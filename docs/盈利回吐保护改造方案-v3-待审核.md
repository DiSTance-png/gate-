# 盈利回吐保护改造方案 v3（待审核）

日期：2026-10-29。状态：方案评审阶段，未修改代码、配置、GitHub 或 VPS。

## 1. 针对刚才“大拉后被止损”的目标

目标不是取消止损，也不是把止损放远。目标是区分三种情况：

1. **没有形成有效浮盈**：原始结构止损继续有效。
2. **已有可兑现浮盈后正常回撤**：保护应锁住至少一部分收益或覆盖成本。
3. **突发行情冲击/结构反转**：不放宽止损；必要时在止损前用受限 reduce-only 降低风险，最终仍以原生保护为最后防线。

大拉可能代表原方向判断已经失效。系统不能为了避免一次止损而把失效交易继续留在场内。

## 2. v3 的核心变化

### 2.1 先工程、后策略

第一阶段只实现并验证：

- 固化真实成交后的初始 E、S0、D0；移损后永远使用 D0 计算 R。
- 仅接管单一、完整、无加仓、无部分成交歧义的风险段。
- guardian 独立于 15 分钟 AI，每 10 秒检查一次；AI 超时不影响保护。
- 所有新增风险写前检查 guard heartbeat、环境、策略版本、持仓修订和 pending 保护意图。
- 保护修改失败、超时或结果不明时，先查原 client_id、order_id、已结束保护单、触发成交和当前持仓；不得换 ID 重复发单。
- Gate 原生保护链路未通过隔离 Testnet 故障验证前，只运行 observe，不启动 enforce。

### 2.2 使用“利润地板”，不使用固定提前止损

设：

- E：实际成交均价。
- D0：初始成交到初始止损的价格风险距离。
- r：当前有利价格移动 / D0。
- MFE：本周期已确认的最高有利 r。
- C：剩余仓位手续费、预计平仓费、已发生资金费和滑点预算。

保护规则：

| 阶段 | 触发条件 | 候选止损 |
|---|---|---|
| S0 | MFE 未覆盖成本 | 保持 S0 |
| S1 | MFE ≥ max(0.6R, 成本覆盖线) | 允许最大亏损降至 0.25R |
| S2 | MFE ≥ 1.0R 且当前价格仍在保护目标一侧 | 移至净保本线 |
| S3 | MFE ≥ 1.5R | 保留 max(净保本线, 0.5 × MFE) |
| S4 | 突发反向冲击且 MFE ≥ 0.8R | 不放宽保护；可按授权减仓 25%～40%，余仓继续受原生止损保护 |

S1/S2/S3 只允许单调收紧，不允许因当前价格回撤而放宽。S4 不是必然市价平仓，只有以下条件同时满足才允许 reduce-only：

- 当前仓位仍能唯一归属本周期；
- 保护覆盖完整且没有未完成保护意图；
- 价差、行情时间和数量可确认；
- 未有相同周期的平仓请求在途；
- 减仓数量不超过本周期可归属数量的 40%。

不能证明时保留原生保护并 fail-closed，不盲目发市价单。

### 2.3 “大拉”识别只用于减风险，不用于放宽止损

突发冲击候选条件使用确定性数据，不依赖 LLM：

- 1 分钟或可用最短周期内，逆向移动达到 `max(0.6 × ATR_15m, 0.35D0)`；或
- 连续两个价格样本逆向穿越结构边界，同时短周期加速度朝反方向；或
- 当前价接近原止损且点差/行情延迟超过安全上限。

该条件只能触发 S4 风险减仓、保护确认或人工复核，不能触发“扩大止损等待反弹”。阈值需通过固定数据回放验证，不直接进入实盘。

## 3. 执行安全设计

### 3.1 优先使用原位修改

先在隔离 Testnet 确认 Gate 当前账户模式支持原位修改保护单并保持 `reduce_only/close/auto_size` 语义。若不能确认，v3 enforce 禁止高频撤旧建新。

若只能撤旧建新，状态必须为：

```text
PREPARED → OLD_CANCEL_CONFIRMED → NEW_SUBMITTED → NEW_CONFIRMED → COMPLETE
```

超时按 client_id、order_id、已结束订单、触发成交和持仓顺序对账；结果不明时禁止第二次提交。持续不明时只升级告警、阻断新增风险，并按经过单独授权的 reduce-only 应急流程处理，不能假称保护已恢复。

### 3.2 guardian 失效时的准入门

guardian 自己不能证明自己健康。所有扩大风险路径在共用写锁内读取权威 guard 状态：

- enforce 心跳不超过 30 秒；
- 环境、账户、策略哈希和持仓修订一致；
- 没有未完成保护修改或 critical 错误；
- 状态时间不能在未来。

不满足时阻断开仓、加仓、突破计划和挂单 AMEND；已有持仓的平仓、保护收紧和恢复对账继续允许。

## 4. 第一阶段明确不做的事

- 不取消原生止损。
- 不因大拉而扩大止损距离。
- 不让 LLM 决定是否绕过确定性保护。
- 不在部分成交、加仓、外部仓位变化或双向歧义时自动接管。
- 不用一分钟最高/最低价假设“必然成交”。
- 不立即上线 S1～S4 参数。
- 不自动应用自进化候选，不改变 Live 开关、杠杆、保证金上限和日亏损熔断。

## 5. 研究和验收

固定对照：

- C0：当前线上逻辑。
- C1：只做工程修复，不改变保护阈值。
- C2：C1 + S1～S3 利润地板。
- C3：C2 + S4 受限减仓。

必须同时报告：

- 扣费净收益、最大回撤、利润因子；
- MFE≥0.6R 后转亏比例；
- MFE≥1.0R 后最终完整止损比例；
- 浮盈保留率；
- 大盈利被提前截断比例；
- 保护空窗、修改失败、重复写和恢复失败；
- S4 减仓后的剩余风险和错误触发率。

回放必须固定成本、滑点、点差、保护确认延迟和同一根 K 线内的先后顺序。缺少逐笔数据时报告悲观/乐观边界，不能把最高价当作成交价。

### 5.1 三道门

1. **工程门**：本地故障测试、进程重启、模型超时、取消/创建歧义、部分成交、加仓隔离、锁竞争全部通过。
2. **执行门**：隔离 Testnet 证明保护修改/恢复和 reduce-only 身份、数量、方向正确；observe 不能替代 enforce 测试。
3. **策略门**：至少 30 个独立持仓周期、4 个周窗口的未调参验证；C2/C3 扣费后收益为正，相对 C1 的收益差区间下界大于零，最大回撤不高于 C1，并在双倍费用/滑点压力下不转为负期望。

任意一门未通过，只能停留在 observe 或研究状态。

## 6. 实施顺序和用户审核点

1. 用户审核本 v3 方案和 S1～S4 研究定义。
2. 本地实现 C1 工程修复，运行全量测试。
3. 本地历史回放比较 C0/C1/C2/C3；若证据不足，不修改实盘策略。
4. 通过本地测试且方案评审无 P0、评分达到 90 分后，才允许准备 GitHub/VPS 更新；更新前仍需把实际参数和回放报告交用户确认。
5. VPS 默认 observe；只有用户明确审核 enforce 参数后才启用交易写路径。

本方案评分只衡量设计质量，不代表收益保证。
